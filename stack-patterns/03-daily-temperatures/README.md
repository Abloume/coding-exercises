# 03 每日温度

> 模式：栈 **C1 单调栈 · 下一个更大元素**（见 [STACK-PATTERNS.md](../../STACK-PATTERNS.md)）

## 题目

给定一个整数数组 `temperatures`（每天的温度），返回数组 `answer`，其中 `answer[i]` 指第 `i` 天之后**需要等多少天**才会出现更高的温度；如果之后不会升高，则为 `0`。

**示例**：`[73, 74, 75, 71, 69, 72, 76, 73]` → `[1, 1, 4, 2, 1, 1, 0, 0]`

## 思路：单调递减栈（存下标）

**为什么要单调栈**：每个元素要问"右侧第一个比我大的元素在哪"——这正是单调栈的标准场景。

**为什么存下标而不是温度**：答案要的是"天数差"，存下标才能算 `i - top`；温度值本身用 `temperatures[stack[top]]` 随时可取。

```go
func DailyTemperatures(temperatures []int) []int {
	n := len(temperatures)
	ans := make([]int, n)
	stack := make([]int, 0, n) // 单调递减栈，存下标

	for i, t := range temperatures {
		// 当前温度高于栈顶那天的温度 → 结算栈顶
		for len(stack) > 0 && t > temperatures[stack[len(stack)-1]] {
			top := stack[len(stack)-1]
			stack = stack[:len(stack)-1]
			ans[top] = i - top
		}
		stack = append(stack, i)
	}

	return ans
}
```

### 核心直觉：弹出栈顶的那一刻，答案确定

栈保持**严格递减**（栈底热、栈顶冷）。遍历到第 `i` 天时，如果它比栈顶那天的温度高，那 `i` 就是栈顶那天**遇到的第一个更高温度**——于是弹出、结算 `ans[top] = i - top`。被弹出的元素不可能再遇到更近的更高温度（因为 `i` 已经在它右边且是第一个），所以结算一次即可，每个元素最多入栈/出栈一次 → O(n)。

### 两个坑

1. **相等不算更高**：判断是 `t >`（严格大于）才弹出，否则 `[30,30,30]` 会错算出 `[1,1,0]` 而不是 `[0,0,0]`；
2. **忘记栈里剩下的下标**：遍历结束后栈里还有元素——它们右边没有更高温度，`ans` 保持初始 0，不需要额外处理。

## 复杂度

- 时间：O(n)（每个下标最多入栈/出栈一次）
- 空间：O(n)（栈，最坏全递增时栈满）

## 关联考点

- 单调栈模板：`for 遍历 → while 栈顶不满足单调性：弹出并结算 → 入栈`
- "下一个更大/更小元素"四问变体：更大/更小 × 距离/值
- 哨兵技巧（84 题）：栈底/栈顶补 0，避免收尾特殊处理
